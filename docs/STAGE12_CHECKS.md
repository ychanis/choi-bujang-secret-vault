# 12단계 실제 요청 확인표

## 기록 원칙

- 이 표는 학생 자기 점검이며 심판 판정이 아니다.
- 검사 대상 커밋과 실제 배포 커밋을 먼저 대조한다.
- 이전 단계의 사용자 확인, 로컬 모의 검사, 이번 배포 실측을 구분한다.
- 아래 항목은 자체 점검 목록이다. 운영 심판의 공식 41종 목록을 뜻하지 않는다.
- 공식 41종은 심판이 제공한 공격 ID와 결과로 별도 대조한다. 공식 목록과 실행 근거가 없으면 미실행으로 남긴다.
- 기존 로컬 검사 32건과 작전실 모의 검사 4건을 41종 통과 수에 합산하지 않는다.

검사 대상 커밋: 미기록
실제 배포 커밋: 미확인
공식 41종 실행 상태: 미실행
공식 41종 통과 수: 미확인

## 실제 API 기록 절차

1. 배포의 /aleph.json에서 커밋을 확인하고 검사 대상 커밋과 대조한다.
2. 브라우저 개발자 도구 Network를 열고 아래 요청을 하나씩 실행한다.
3. 실제 HTTP 상태와 필요한 최소 결과만 기록한다. 화면 성공 문구만으로 판정하지 않는다.
4. 응답의 X-Request-Id를 기록한다. 없으면 X-Vercel-Id를 사용하고 헤더 이름도 적는다. 둘 다 없으면 미제공으로 남긴다. 임의 ID를 서버 요청 ID로 만들지 않는다.
5. 확인 시각은 ISO 8601과 시간대를 기록한다. 클라이언트 기록 시각과 서버 시각을 구분한다.
6. 금지 요청은 거부 응답과 자료 노출·변경 없음까지 확인한다. 403 하나만으로 소유권 규칙 검증 완료라고 하지 않는다.
7. 정상 요청은 승인된 기기에서 실행한다. 타인 자료 시험도 정상 서명을 붙여 기기 검사에서만 막힌 결과와 구분한다.
8. 작전실의 요청 ID로 Vercel 서버 로그를 찾아 규칙 목록·기기 상태·확인 시각을 대조한다.
9. 인증 헤더·쿠키·서명·기기 지문·사용자 ID·메모 제목과 본문은 표에 넣지 않는다. Network 전체 HAR를 그대로 제출하지 않는다.
10. 조건을 준비하지 못했거나 요청을 보내지 않았으면 미실행으로 남긴다.

## 연속 공격 확인

무인증 → 타인 메모, 미등록 기기 → 회수 기기,
복구 → 서명 없는 변경 → 구역 밖 조회를 같은 배포 커밋에서 순서대로 실행한다.
각 요청은 위 표의 별도 행으로 남기고 요청 ID와 시각을 보존한다.
공격 전후 승인된 정상 기기의 본인 조회도 확인한다.
회수는 별도로 준비한 시험 기기만 대상으로 하며 전체 기기를 회수하지 않는다.
요청 사이에 배포가 바뀌면 같은 제출본의 연속 시험으로 기록하지 않는다.
